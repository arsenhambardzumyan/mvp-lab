What the audit contains

  • Up to 10 issues ranked by severity and likelihood. Each has the file and line, the quoted code, the impact in plain words, a concrete fix and an effort estimate. I do not pad the list: if I find fewer, you get fewer.
  • A checklist marked pass / flag / not applicable: secrets in the repo, exposed config, missing auth checks, input handling, CORS and rate limiting, webhook signature checks, debug mode, dependencies with known CVEs, silent error handling.
  • A one-page fix plan: what to fix before launch, this month, or later.
  • A list of what I ran (for example npm audit) with the result, and a list of what I could not verify.
